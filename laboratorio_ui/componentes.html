🎨 Rediseño de Configuraciones

4 mockups · SR1–SR4

Propuesta de rediseño para la pantalla de Settings: menos texto, agrupación iOS-style, iconos semánticos y jerarquía visual clara.

📐 Principios del Rediseño

  • Eliminar subtítulos redundantes: El nombre del setting debe ser suficientemente descriptivo. Solo mantener descripciones en opciones no obvias (ej: API key).
  • Agrupación iOS-style: Cards con bordes redondeados y título en uppercase encima, como iOS Settings. Cada grupo tiene un máximo de 5–6 rows.
  • Iconos semánticos coloridos: Cada row tiene un icono de 30×30px con fondo de color (como iOS), eliminando la necesidad de texto explicativo.
  • Controles inline: Los segmented controls y toggles van inline en la misma row, sin texto descriptivo debajo.
  • Chevron → detalle: Las opciones complejas (API key, elevación) muestran el valor actual + chevron. Tap abre sub-pantalla.
  • Reducción de texto: ~65% — De ~280 palabras visibles actuales a ~100 palabras en el rediseño.

Reglas para reducir verbosidad:
1. Si el label es autoexplicativo (ej: "Fila terminal", "Vibración"), no agregar subtitle.
2. Si el control es un toggle, el nombre ya implica activar/desactivar: no escribir "Activa X para..."
3. Segmented controls inline: no necesitan texto debajo describiendo cada opción. El usuario entiende "Toque" vs "Mantener".
4. Para opciones complejas: mostrar valor actual + chevron. La explicación va en la sub-pantalla de detalle.
