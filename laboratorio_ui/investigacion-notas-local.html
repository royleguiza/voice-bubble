Sí, es viable — y lo más limpio para Notas es un camino híbrido en cascada.

Hoy hay motores que corren en gama baja con 39–63 MB de modelo y unos 200–300 MB de RAM en pico. Si el sistema ya trae reconocimiento on-device, úsalo gratis. Si no, descarga sherpa-onnx + Moonshine Base ES (~63 MB, on-demand). El cloud Groq se queda solo como fallback que el usuario pide.

Contexto del proyecto

Hoy la sección Notas graba un WAV y lo envía por CloudSttService a Groq Whisper turbo (nube). El modo Local offline fue removido en el Hito 2 (decisión del dueño, 2026-08-22): se puede restaurar desde git, pero su regreso estaba pospuesto.

Reglas del repo que condicionan cualquier reintroducción:

  • Flutter, Android only, minSdk 28.
  • No subir binarios grandes al repo → modelos solo con descarga on-demand.
  • Preferir modelos ≤ 80 MB cuantizados (tiny/base).
  • El audio solo sale a internet si el usuario inicia la transcripción.
  • El CI de hoy publica APK solo arm64; los gama baja muy viejos suelen ser arm32 (riesgo a considerar).
Implicancia de alcance Reintroducir un motor local solo para Notas requiere ok explícito del dueño: no es un empujón accidental, contradice una decisión registrada.

Opción 1 · SpeechRecognizer del sistema

API nativa de Android

SpeechRecognizer.createOnDeviceSpeechRecognizer(). El modelo lo trae (o descarga) el sistema o el fabricante, no nuestra app.

+0 MB en el APK · calidad OEM · ML Kit Basic desde API 31

A favor

  • Cero peso y cero mantenimiento de modelo.
  • En Android 16+ hay motor embebido (~50 MB en partición system).
  • ML Kit GenAI STT: Basic desde API 31; Advanced en Pixel 10/11.
  • Si funciona, es lo más simple posible.

En contra

  • Muchos fabricantes borran o estropean el servicio offline.
  • EXTRA_PREFER_OFFLINE está deprecado o ignorado en varios ROMs.
  • En Android ≤ 15 el default suele ser nube.
  • Calidad fragmentada (nombres propios, acentos).
  • Hay que checkear isOnDeviceRecognitionAvailable siempre.
Veredicto parcial Excelente como fallback gratis si el equipo lo trae. No confiar en ello como único motor.

developer.android.com → SpeechRecognizer · ML Kit GenAI Speech Recognition · Android 16 OnDeviceAsrEngine.

Opción 2 · Vosk

El clásico de gama baja

Streaming real con parciales cada ~200 ms. Apache 2.0 · AAR oficial vosk-android. Probado en Raspberry Pi, relojes y celulares de entrada. En audio limpio el modelo pequeño español rinde cerca de la referencia Whisper; en audio de teléfono empeora más.

ModeloTamañoWER españolRAM
small-es-0.42recomendado móvil 39 MB ~16% (CV) · ~11% (MLS) ~80–300 MB
es-0.42 (grande) 1.4 GB ~5–10% ~1.6 GB · servidor

A favor

  • 39 MB y muy poco RAM.
  • Español dedicado (no multilingüe genérico).
  • Streaming estable para la UI de Notas.

En contra

  • Calidad por debajo de Whisper base.
  • Integración Flutter menos pulida que sherpa (AAR/FFI).
  • Dominios médico/legal: WER de 25–30% sin fine-tune.

alphacephei.com/vosk/models · vosk-api · benchmark street-vendor / edge ASR.

Opción 3 · sherpa-onnx + Moonshine ES

Recomendada · encaja con Flutter

Existe package Flutter en pub.dev: sherpa_onnx (1.13.x). Soporta arm64 y arm32 (clave para gama baja vieja), trae VAD Silero (corta silencio → evita OOM en notas largas) y sirve para streaming y batch con el mismo runtime.

runtime ~7 MB · Moonshine ES ≈63 MB · 51× vs whisper.cpp en Android

Modelos en español disponibles

ModeloPesoNota
Moonshine Base ES quantizedencoder 20 + decoder 42 + tokens ≈63 MB Favorito · sin ventana fija 30 s · ideal notas cortas
Whisper Tiny (multi) ~100 MB 99 idiomas · RTF ~0.07 en S10 con sherpa
FastConformer CTC ES (NeMo) medio 1424 h entrenamiento · streaming simulado
Zipformer streaming “Kroko” ES medio streaming real
Parakeet TDT 0.6B (25 europeos) ~670 MB incluye ES · demasiado para gama baja
Dato duro del benchmark VoicePing (2026) En Android, sherpa-onnx es ~51× más rápido que whisper.cpp con el mismo Whisper tiny. Para un teléfono de bajos recursos, el runtime importa tanto como el modelo.

A favor

  • Package Flutter listo en pub.dev.
  • Español nativo (Moonshine ES 2026-02).
  • arm32 + arm64 · descarga on-demand · ≤ 80 MB.
  • VAD + streaming + batch en un solo stack.

En contra

  • APK +~7 MB (o +0 si se usa solo sherpa-ncnn).
  • Integración FFI/mic más trabajo que un MethodChannel.
  • Hay que probar WER real con acentos del usuario.

k2-fsa.github.io/sherpa/onnx · pub.dev/packages/sherpa_onnx · releases asr-models · Moonshine models-v2 (es).

Opción 4 · whisper.cpp

Solo batch · no streaming

ModeloDiscoRAMUso
tiny q5_1 31 MB ~273 MB (fp16) el más pequeño empaquetable
tiny q8_0 ~42 MB un poco menos mejor fidelidad
base q5_1 57 MB ~388 MB si hay RAM de sobra
Problema conocido en Android El modo streaming va muy lento (reportes de 5–7 s por ~1 s de audio; la latencia se acumula). El modo batch (grabar → parar → transcribir) sí va bien. Y con el mismo modelo, sherpa-onnx rinde ~51× mejor en Android.

Conclusión: solo tiene sentido si el flujo de Notas es estrictamente tap grabar → tap stop → esperar texto y se acepta la espera. No sirve para dictado en vivo.

github.com/ggerganov/whisper.cpp · discussion #3567 (streaming Android) · HF ggml models.

Calidad esperada en español

Orientativo (WER = % de palabras incorrectas; más bajo es mejor). No es un benchmark propio: son números públicos de papers y repos. Las celdas de WER mezclan fuentes y condiciones distintas — leer la nota al pie.

Sistema Android offline 0 variable por OEM si existe
Vosk small-es 39 MB ~11–16% sí · aceptable

Whisper tiny fine-tune ES (HiTZ) ~40–100 MB 19.6% (CV13) ok

* Sobre Moonshine Base ES No hay WER público «Moonshine Base ES» en Spanish Common Voice, pero la familia monolingüe de 27M rinde ~48% mejor que Whisper tiny y a la par de Whisper medium en varios idiomas (paper Flavors of Moonshine). Esperable ≥ a tiny multi.

Para notas personales (no legal ni médico), 10–16% WER suele ser usable: el usuario lee y corrige. Si el dueño exige calidad turbo-cloud, el local en 1–2 GB no la iguala.

Arquitectura recomendada

Híbrida en cascada, respetando privacidad y las reglas del repo. El orden importa: cada paso solo se evalúa si el anterior falló.

  1. ¿Existe STT on-device del sistema?

    Checkear isOnDeviceRecognitionAvailable / checkRecognitionSupport. Si sí → SpeechRecognizer offline (coste 0).

  2. Si no existe o la calidad no da

    sherpa_onnx + Moonshine Base ES: descarga on-demand ~63 MB la primera vez, cache local, jamás en el repo.

  3. Fallback cloud (opcional, a petición del usuario)

    Groq actual solo si el usuario lo permite — ya es el contrato de privacidad vigente.

  4. Mismo path de UX que hoy

    Grabar WAV → motor elegido → texto → NotesService. Cambia el backend, no la pantalla.

  5. VAD Silero siempre

    Corta silencio por segmentos de frase → memoria plana en notas largas, sin OOM.

Por qué no solo una Solo sistema = frágil (OEM). Solo modelo = peso extra para todos aunque el sistema ya sirva. Híbrido = óptimo en gama alta y gama baja, y la privacidad mejora sin empeorarle a nadie.

Riesgos y decisiones pendientes

  • AlcanceDecisión dueño

    AGENTS/README dijeron «nada de notas» y luego el local se pospuso. Reintroducir motor local solo para Notas necesita ok explícito.

  • APKTamaño

    +~7 MB por sherpa (o +0 con solo sistema/Vosk). El modelo no va en el APK: solo descarga.

  • arm32ABI

    Si el objetivo es gama baja muy antigua, hoy el CI solo sube arm64. Habría que evaluar split armv7 o universal (sube storage en Actions).

  • WER ~10–16%Calidad

    Local no iguala al turbo cloud en 1–2 GB. Sirve para notas; no para transcripción profesional/legal sin corrección.

  • Notas largasBatería

    Limitar a grabación corta por toque (flujo actual tap→tap) + VAD. Evitar streaming continuo infinito.

  • PrivacidadGanancia colateral

    Con motor local, el audio de Notas no sale del teléfono — refuerza el contrato de privacidad sin tocar la UI.
